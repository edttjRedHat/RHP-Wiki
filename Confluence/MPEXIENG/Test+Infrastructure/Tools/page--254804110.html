CI Operator Emulator

During test and development phase, it will be significantly more efficient if the CI Operator Step script can be executed in local env., instead of executed via CI Operator Job rehearsal (as it takes time to schedule it, not to mention it is a non-interactive session so real time inspection can not be performed).

Since the CI Operator Step script is executed inside Container, then it should be possible to start local Container using the same Container Image used to execute the Step. Having an interactive local Container, improve the development cycle due to faster iteration for Step script re-execution. What is needed is this Container Image.

This tool will automate the creation of Pre-Test (run all previous Steps of target Step) and Image Retriever (build the Step Container Image) CI Operator Jobs, so they can be pushed to a dummy GitHub Pull Request (PR).

After the Pre-Test Job rehearsal, the test environment is ready to execute the target Step.

After the Image Retriever Job rehearsal (which should be quick), the Container Image can be downloaded (within certain amount of time, before the Job's NameSpace in the executing CI Operator Build Cluster is deleted). Generally speaking we only need to do this 1x only for every unique Container Image used to execute the Step.

Once the Container Image is available locally, the Container (with env. settings mimic the Container created on the CI Operator Build Cluster) can be started. And inside this local Container, the corresponding Step Script can be executed with much faster iteration and providing real time inspection capability that can not be done during Job rehearsal.

Please follow this instruction to use this tool:

  1. Execute the script.

    solidCI Operator Emulatorauto100%hidetop1632

  2. Run make update and push the generated Image Retriever CI Operator CI configuration file, along with changes from make update, to a dummy PR (MKA).

    solidPushing to Dummy PRauto100%hidetop558

    Dummy PR

    This Dummy PR should NEVER get merged. To ensure this, do the following:

    • Make SURE there is [WIP] in front of dummy PR subject, so it does not bother people requesting review.

    • Remove any reviewers, so they do not get bothered with emails (put /uncc @reviewerNames ... in a comment box).

    • Add do-not-merge/hold label (put /hold in a comment box).

    • Set the PR to Draft.

    Please try to re-use this Dummy PR (keep it open and for next image retrieval just do git push --force ...) as much as possible, otherwise there will be tons Dummy PRs generated.

  3. Rehearse the CI Operator Emulator Jobs and wait until the rehearsed Job is completed.

    1. For Pre-Test Job, wait until it reaches Step run-prior-steps--0, where the job is held for 4 H (this stage can be controlled via ci--wait--test command, execute ci--to-do for details).

    2. For Image Retriever Job, wait until it is completed.

  4. Login to the executing CI Operator Build Cluster and obtain the CLI login command to the Build Cluster. Copy the CLI login command.

    solidGet CLI Login Command

  5. In the CI Operator Emulator session, start ci--pull--ctr-img [<n>] (execute ci--to-do for details on <n>) to download the Container Image. For the first time, it will start the login session, then execute the copied CLI login command inside that login session and exit the login session. If this step is repeated and the login session is still active, it will not ask to login again.

    solidDownload Step's Container Imageauto100%hidetop720

  6. In the CI Operator Emulator session, start ci--start--ctr, to start the Container using the downloaded Container Image. Execute the corresponding Step script. This step can be repeated if the Container session is terminated.

    solidStart Local Containerauto100%hidetop216

    Unfortunately the information about each secret, inside where they are mounted in the Container, can not be obtained automatically. Follow the instruction where to put the secrets. Do NOT use CI owned secrets. Obtain individual owned secrets accordingly.
